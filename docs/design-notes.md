# 设计记录

这份文档记**为什么是现在这样**：关键取舍、实测结论、以及被否掉的方案。
用法看 `usage.md`，代码结构看 `architecture.md`。

一条纪律：这里的每条结论后面都跟着**当时跑出来的数字**。没有数字的判断写成"判断"，不写成结论。

---

## 1. 定位：为什么不做爬虫

**取舍**：不做请求伪装（UA / 代理 / 指纹），改用用户自己的浏览器和程序去复制。

理由是那场军备竞赛打不赢：站点检测的是"这是不是一个真人操作的进程"，
而伪造永远只是无限逼近。换成让真浏览器发请求，指纹、IP、Cookie、会话全都是真的，
不需要绕过任何东西。

**代价**：必须有一个正在运行的浏览器 / 目标窗口，且需要人先登录。
这条代价换来的是覆盖面——付费墙后的后台、只有客户端才看得到的列表，
爬虫永远进不去。

---

## 2. 全自动按键，不是人手动复制

**被替代的方案**：最初的设计把人手动 `Ctrl+A` / `Ctrl+C` 当作主线，脚本只负责切分。

这个方案被否掉，因为那样它只是个"剪贴板转表格"，跟这个项目要做的事无关。
现在人只在三处出现：登录、过验证码、确认第一页。其余全自动。

**代价**：要跟操作系统的按键通道打交道，于是有了下面 §4–§7 那一堆坑。

---

## 3. `anchor` 必须和 `anchor_next` 成对

**实测结论**：单看一行判断"这是不是新记录"是错的。

"昵称"和"正文里的短行"在长度上没有任何区别。只按长度阈值切，一条记录会被切成两条，
而每条看起来都像模像样——这是最坏的一类错误：**形状对、数据错**。

改成"这一行像标题"**并且**"下一行是裸日期"两行联合，才能分开。
因为正文里提到日期的句子几乎不会只有一个日期。

**已知歧义**：三个等距日期出现在一片平面文本里时，局部证据上和"三行一条的记录"无法区分。
工具会切，因为拒掉它会误杀真实的短记录。这条取舍写在代码注释里。

---

## 4. 周期检测必须有「对比」，否则会编造结构

**现场**：把 `books.toscrape.com` 全选复制，得到 137 行，其中 115 行是短分类名。
`infer` 报 `S1 60 行 × 2 列`——它把分类菜单切成了"两列记录"。

**根因**：只要"按 p 取模分组后每组主导形状一致"就接受周期。所有行同属 `short` 类时，
p=2 的一致率是 1.00，但两个偏移位置的主导类**相同**，等于没有信息量。
散落少量异类行就能让"主导类看起来不同"，所以这个判据挡不住。

**修法**：要求每个偏移位置的**纯度**（该 offset 内主导类占比）不低于阈值，
且不同 offset 的主导类不能全一样。

**阈值是扫出来的**（`_probe/period_threshold.py`，候选 0.5–1.0）：

| 样本 | 纯度 |
|---|---|
| 真实周期（ecom 5 行块、4 行块、7 行块、kv 交替） | 1.00 |
| 编造周期（平铺页 + 散落离群行） | 0.50 – 0.58 |

**0.7 落在这道间隙里，不是贴着边缘**。选 0.6 会放进一个两日期假周期；
0.75 以上会开始误杀真实短记录。

**已知残留**：三个等距日期仍会被切成周期。这是上面 §3 那条歧义的同一件事，没有更好的局部证据。

---

## 5. 周期属于「区域」，不属于整页

**被替代的方案**：一开始在全页行序列上算一个周期。

失败得很干净：`books` 页真实结构是从第 57 行开始的干净三行块，
但前 56 行是导航和页头，全页偏移被它们污染，检测结果是 `(0, 0)`——**有真实周期却检测不出来**。

**改法**：先在 class 变化点切出候选区域，区域内算周期，再按纯度打分取最好的那个。
导航行归导航行，商品块归商品块。

顺带解决了反方向的错：平铺页面不会被整页编造成周期。

---

## 6. `S0` 只认真正的表格行

**现场**：`iana.org/domains/reserved` 全选复制得到 43 行，其中只有第 10–21 行是 4 列真表格。
`infer` 报 `S0 42 行 × 1 列`，第一条是导航文字 `Domains=Protocols`。完全编造。

**根因**两处：列数在**全页所有非空行**上取众数（多数行没有 Tab，众数是 0 Tab → 1 列），
然后所有行都按 1 列切成记录。

**修法**：只在含 Tab 的行上算列数；只有正好 N 列的行才算记录；其余进未识别。
一行 Tab 都没有时直接退到 S4，**不从虚无里编列**。

修复后同一份剪贴板：`S0 11 行 × 4 列，未识别 31 行`，守恒 43/43。

## 7. E1：CDP 发真按键，但必须先确认标签页可见

**实测**（`_probe/m2_4_*`，N=8 与 5 轮交替）：

| 方法 | 复制成功 | 是否移动前台 |
|---|---|---|
| `Page.bringToFront` | 8/8 | 0/8（窗口可见时） |
| `Browser.setWindowBounds` | 0/5 | 照样移动前台 |

`setWindowBounds` 被否掉：它既不解决复制，还会移动前台。`bringToFront` 是唯一可用的。

**但**：Chromium 拒绝为**隐藏**标签页写剪贴板。所以窗口最小化时，`bringToFront`
必然短暂借走前台。这不是缺陷，是平台约束——产品必须显式做两件事：
借之前记下原前台窗口，采完还回去；报告里写明"临时提到前台，已把焦点还给原来的窗口"。

**验收因此拆成三种情形**，一条命题盖不住：

| 情形 | 期望 |
|---|---|
| 窗口可见、标签不活动、用户在别处 | 完全不打扰（8/8 前台不动） |
| 浏览器最小化 | 借用前台，采完归还（归还落地验证过） |
| 修不好 | 发键之前报错，不是发了再说 |

## 8. E2：三个把「看起来成功」当成「成功」的坑

### 8.1 `SetForegroundWindow` 返回非零 ≠ 切过去了

实测 7/8 成功、1/8 返回真但前台没变。必须用 `AttachThreadInput` 挂到目标线程再切，
并且**切完用 `GetForegroundWindow` 复核**，不能信返回值。

### 8.2 切过去了，键还是没进去

Win11 记事本（WinUI3）的焦点停在 `InputSiteWindowClass`，一个不接收文本输入的宿主窗口。
按键发过去被它吃掉。

**修法**：`focus_text_control` —— 只在目标窗口里找**可见的文本控件**（RichEdit / Edit）并把焦点给它；
找到两个可见文本控件就拒绝（不知道该给谁），一个都没有也不算错（有些程序直接把焦点给主窗口）。

### 8.3 最危险的一个：复制到了地址栏

Edge 在前台时，`Ctrl+A` / `Ctrl+C` 可能作用在**地址栏**而不是页面。结果是：
剪贴板有内容、解析成功、守恒通过、报告干净——**数据是当前网址**。

**修法**：发键前先按 `Esc` 把焦点从浏览器 UI 拉回页面（实测 8/8 恢复页面焦点，
且原本就在页面时按 `Esc` 4/4 不破坏 `location.href`），然后对剪贴板内容做硬校验：
如果内容长得像"网址 + 标题"，报错而不是当成数据。

**教训**：这条坑的可怕之处不是失败，是**成功得太像成功**。

## 9. 浏览器错误页会被当成数据

**现场**：一个标签页实际停在 `ERR_CONNECTION_TIMED_OUT`，`harvest` 照样复制、照样切分、照样给出干净报告。

**修法**：复制之前判断页面是不是错误页（`chrome-error://` / `#main-frame-error` / 空标题），
命中就报错停手。同理还有验证码墙（Cloudflare / hCaptcha / reCAPTCHA / 滑块），
命中就停下来等人处理，不硬闯。

## 10. 静默丢数据的三道闸，以及它们各自的边界

| 闸 | 能证明什么 | 证明不了什么 |
|---|---|---|
| 行数守恒 | 没丢行 | 没切错 |
| 卡自带样本 + 独立答案键 | 规则在这个样本上是对的 | 站点改版后仍然对 |
| `record_lines` / `required` 形状校验 | 这一页的记录形状符合卡的声明 | 值本身对不对 |

第二道之所以要把答案键放在卡**外面**：如果期望值由工具自己生成，改坏规则时期望值同步变坏，
永远都能通过，那这个测试等于没有。

第三道之所以是**警告不是过滤**：形状偏离的记录仍然是数据，丢掉它才是真的丢数据。

## 11. 被替代的方案清单

| 被替代 | 替代者 | 为什么 |
|---|---|---|
| 人手动 Ctrl+A / Ctrl+C 作主线 | 全自动按键 | 否则只是个剪贴板转表格 |
| 全页单一周期 | 区域化周期 | 导航行污染会让真实周期检测不出来 |
| 只看"按 p 取模一致率" | 加纯度地板 + 主导类必须不同 | 一致率 1.00 也可能是没有信息量 |
| `S0` 在全页行上算列数 | 只在含 Tab 的行上算 | 否则导航文字会被编成表头 |
| `Browser.setWindowBounds` 翻出隐藏标签 | `Page.bringToFront` | 实测 0/5 复制成功，还照样移动前台 |
| 信 `SetForegroundWindow` 返回值 | `AttachThreadInput` + 事后复核 | 7/8 会撒谎 |
| 把焦点给窗口就发键 | `focus_text_control` 只认可见文本控件 | WinUI3 宿主窗口吞键 |
| 每页四个文件分别原子写 | 整页 rename 发布 | 四个原子写组合起来不是原子的 |
| 冲突只有一种桶 | 内容变更 / 身份冲突分开 | "更新了"和"主键撞了"是两件事 |
| `run -d` 接受但不用 | 统一走 `flow.Committer` | 参数被接受、目录没建、还不说 |
| 用请求 URL 当来源 | `requested_url` / `observed_url` 分开 | 回退换通道可能落到另一个地址 |
| `span` 标记找不到时退化成整条记录 | 严格报空 + `before?:` 显式可选 | 否则「商家回复」拿到整条记录，填满了却是错的 |

## 12. 已知边界（不打算"解决"的）

- **纯文本切分本质是启发式**。站点结构变了而锚点还在，工具可能切出一张每列都有值、
  每个值都错位的表。所以才有形状校验、答案键回归、以及 `--dry-run` 先看后存。
  但它不能保证 100% 正确，任何声称能保证的工具都在骗人。
- **图片里的字**不做（那是 OCR）。
- **要点击才展开的深层内容**不自动展开。
- **纯 Canvas 渲染**读不到。
- **桌面通道的滚动位置**没有任何 Win32 调用能还原，所以续采必须显式声明。
