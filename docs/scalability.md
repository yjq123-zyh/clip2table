# 增量存储资源记录

环境：Windows 11、Python 3.12.6。输入每页 100 行、每行 6 字段，使用本地 HTTP 服务；实体 ID 确定生成。
数据构建各执行一次，日常追加、查询、导出和重算各执行三次，耗时取中位数。索引重建单独计时。
峰值内存为所在进程累计 PeakWorkingSetSize，进程写出量包含源记录、元数据与 SQLite。

## 存储主体测量

以下为本轮增量存储完成时的采集与查询记录，后续补入运行结束快照、事件恢复及人工决定索引。

| 工作量 | 1 万行 | 10 万行 | 100 万行 |
|---|---:|---:|---:|
| 从空库采集（秒） | 12.26 | 137.77 | 1492.59 |
| 采集峰值（MiB） | 49.5 | 55.9 | 90.9 |
| 追加 10 页（秒） | 1.321 | 1.590 | 1.618 |
| 暖查询前 100 行（秒） | 0.0083 | 0.0092 | 0.0081 |
| current CSV（秒） | 0.176 | 0.877 | 7.459 |
| current XLSX（秒） | 0.293 | 1.846 | 16.909 |
| history CSV（秒） | 0.169 | 1.056 | 9.186 |
| history XLSX（秒） | 0.348 | 2.507 | 23.258 |
| 重建索引并查询（秒） | 2.28 | 19.25 | 170.41 |

从 10 万行到 100 万行，采集峰值增长 1.63 倍，追加相同 10 页的中位耗时增长 1.02 倍。
采集期间 run/operation/revision 的累计 JSON 写出量增长约 10 倍，进程累计写出量增长 10.39 倍。
暖查询读取前 100 行时，捕获与解析正文读取入口调用次数为 0。

相同的 100 页分为 100 次运行时，采集耗时 32.45 秒；一次运行采集 100 页为 12.26 秒。
记录包括修订快照及选择开销。

v0.3.0 在同机 100 页负载下，采集 36.60 秒，读取前 100 行 1.096 秒；本轮对应为 12.26 秒和 0.0083 秒。
该版本对照使用 100 页负载，规模增长比较使用本轮的 1000/10000 页。

## 导出状态

导出状态保存固定查询、字段和产物清单，完整值及损失说明写入伴随文件。
256 个各 33000 字符的单元格全部保存原值，summary 操作状态 5127 字节，响应 1373 字节。

## 复现

```powershell
python _dev/benchmark_storage.py --pages 1000 --out out/bench-1000 --full
python _dev/benchmark_storage.py --pages 10000 --out out/bench-10000 --full
python _dev/benchmark_storage.py --pages 1000 --out out/bench-1000 --query-only
```

测量结果保存代码摘要、环境、各操作耗时、峰值、进程 IO、JSON 写出量和数据目录大小。
`--existing` 在已有负载上测量日常操作，`--single-pages` 将初始采集拆为逐页独立运行。
JSON/DOM 的值、覆盖、来源和业务答案由结构与场景回归单独验证。
