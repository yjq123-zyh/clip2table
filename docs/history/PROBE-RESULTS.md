## 结论：方案不需要改设计

四条全部落在方案预设的「过」分支里，没有一条需要动用 §11 表里的退路。

两个额外收获，比原型本身更有价值：

1. **E1 不依赖窗口在前台**。这一点反直觉，且直接推翻了我在 p1/p1b 里的错误结论。当时 `/json/list` 的第一个 target 是 `edge://sync-confirmation-dialog/`，按键全打到了后台标签页上，我误判成「窗口不在前台所以按键不生效」。实际上选对 target 后，`Input.dispatchKeyEvent` 在后台标签页也能到达页面（`document.hasFocus()` 为 true，页面 keydown 监听器 100% 命中）。**当时我据此写「E1 采集期间完全不打扰用户」——这句是错的，后面被推翻，见下方更正。**

   **更正（M2#4 验收期间实测）**：按键能到后台标签页，但**Chromium 拒绝为隐藏标签页写剪贴板**（隐藏时 keydown 照样触发、剪贴板序列号不动）。复制要发生，标签页必须是 `visible`。三种情形分别实测：
   - 窗口可见、只是另一个标签页是活动标签、用户在别的程序 → `Page.bringToFront` 修好它，**OS 前台不动**（8/8，`fg_moved` 0/8）。这是常见情形，确实不打扰。
   - 浏览器窗口**最小化** → `Page.bringToFront` 会还原窗口并**抢走前台**（5/5 归还成功）。`Browser.setWindowBounds` 是错的工具（同一状态下 0/5 翻可见，且照样移动前台）。
   - 可见性修不回来 → 发键之前就报错退出，绝不发键（发了只会得到「剪贴板没变化」，把工具自己的问题栽给页面）。
2. **E2 真正的风险不是发键，是打错窗口**。见下方事故。

## 事故记录（必须写进产品约束）

**现象**：p2b 探针用「启动前后窗口句柄差分」定位目标记事本，但差分拿到的是一个**已存在的空白窗口**（`无标题 - Notepad`，pid 37644 与用户正在编辑的 `舆情清洗方法清单_v002.md` 同进程），于是 78 个字符被敲进了用户正在编辑的文档缓冲区。

**影响**：仅内存缓冲区被改，**磁盘文件未受影响**（`LastWriteTime` 仍是 2026-10-17 21:53:36、长度 10538 bytes、sha256 `982E9DD9...794946` 未变）。已用 Ctrl+Z 撤销，标题前 `*` 已消失；剪贴板已用 `set_text` 还原为事故前内容（5178 字符，逐字符核对相等）。

**根因**：不是 SendInput 失灵——它工作得过于好。是探针**在发任何键之前没有校验目标身份**，把「新出现的窗口」当成了「我的窗口」。

**由此定下的产品约束（写进 §8 SKILL.md 禁止段与 §2.2 第①步）**：

1. `desktop` 通道发键前必须过**三关**：目标 hwnd 有效 → `window_text` 与卡里 `[target].title` 正则匹配 → 该窗口所属进程的**文档是否有未保存修改**不可知时，默认拒绝操作并要求 `--force`。
2. **禁止任何形式的「往窗口里打字」**。本工具只按 `Ctrl+A` / `Ctrl+C` / `PageDown` / `Ctrl+Home` 四个键，全部是只读动作。原型的 `type_unicode` 是探针专用，不进产品代码。
3. 发键前后各记一次 `GetForegroundWindow`，采集结束**必须**归还；归还失败要在报告里显式写出，不许静默。
4. 验收里加一条负向测试：构造「目标窗口已关闭」与「目标标题变了」两种情形，工具必须报错退出，且**剪贴板序列号不变**（证明一个键都没按）。
